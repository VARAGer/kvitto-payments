# Работа над Kvitto Payments API

- Источник требований — исходное тестовое задание, REQUIREMENTS.md и явные уточнения пользователя.
- Сохраняй понятную Junior-разработчику архитектуру. Общую бизнес-логику держи в небольших функциях; дополнительные слои вводи только при конкретной необходимости.
- Все денежные суммы — целые копейки. Не используй float для денег.
- Соблюдай pending → succeeded/failed и succeeded → refunded. Изменение статуса проверяй атомарно в БД.
- Сохраняй уникальность Idempotency-Key и возврат первого платежа при повторе.
- Проверяй подпись банка по исходным байтам тела через HMAC-SHA256 и compare_digest. WEBHOOK_SECRET не хранить в репозитории.
- Схему БД меняй миграциями Alembic; не добавляй create_all в запуск приложения.
- После изменений запускай подходящие тесты. Перед сдачей обязательны `ruff check .`, `pytest -q`, проверка миграций и актуальности README/STUDY_GUIDE.md.
- Используй временную БД для проверок. Не удаляй пользовательскую БД или Docker volume.
- Не меняй рабочий код ради стиля и не добавляй необязательные зависимости.
- Обнаруженные ошибки исправляй и покрывай тестом. Не заявляй успешный запуск Docker/CI без фактического подтверждения.
