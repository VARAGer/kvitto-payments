# Квитто Payments API

Небольшой API оплаты курсов: тарифы, создание и получение платежа, уведомление банка о статусе. Денежные суммы хранятся и передаются целыми копейками.

## Стек

Python 3.11+, FastAPI, Pydantic v2, SQLAlchemy 2, SQLite, pytest и httpx. Docker и миграции в тестовом задании необязательны, поэтому таблицы создаются при старте приложения через `create_all`. Это подходит для нового учебного проекта; изменение схемы существующей БД потребовало бы миграций.

## Запуск

Из корня проекта:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
uvicorn app.main:app --reload
```

На системе, где команда `python3.11` отсутствует, используйте установленный Python версии 3.11 или новее. Приложение доступно на `http://127.0.0.1:8000`, документация — на `/docs`. По умолчанию используется файл `payments.db` в текущем каталоге; при первом старте создаются таблицы и три тарифа.

Необязательная переменная окружения `DATABASE_URL` задаёт адрес БД. Например:

```bash
export DATABASE_URL=sqlite:///./payments.db
```

Образец находится в `.env.example`. Файл `.env` автоматически не читается: если используете его, экспортируйте переменные в окружение перед запуском.

## Тесты

```bash
pytest -q
```

Тесты используют отдельную временную SQLite-базу и проверяют тарифы, суммы, промокод, рассрочку, повторный ключ, валидацию, 404, все 16 пар статусов, конкурентные вебхуки и внешний ключ. Результаты реального запуска и сверки с ТЗ находятся в `AUDIT_REPORT.md` и `REQUIREMENTS.md`.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /tariffs` | `200`, тарифы |
| `POST /payments` | `201`, новый платёж; `200`, повтор `Idempotency-Key` |
| `GET /payments/{id}` | `200`, платёж; `404`, если не найден |
| `POST /webhooks/bank` | `200` при допустимом переходе; `404` без платежа; `409` при запрещённом переходе |

Невалидные данные дают стандартный ответ FastAPI `422`. В `POST /payments` метод бывает `card`, `sbp` или `installment`. Для рассрочки обязательно передать `installment_months`: `3`, `6` или `12`. Промокод `KVITTO10` уменьшает цену на 10% независимо от регистра. Поле `amount` — итог к оплате, `discount` — размер скидки, оба в копейках. Уведомление банка принимает статусы `pending`, `succeeded`, `failed`, `refunded`, но менять их разрешено только по правилам задания.

Примеры запросов:

```bash
curl http://127.0.0.1:8000/tariffs

curl -X POST http://127.0.0.1:8000/payments \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: order-123' \
  -d '{"tariff_id":2,"email":"student@example.com","method":"installment","installment_months":3,"promo_code":"kvitto10"}'

curl http://127.0.0.1:8000/payments/1

curl -X POST http://127.0.0.1:8000/webhooks/bank \
  -H 'Content-Type: application/json' \
  -d '{"payment_id":1,"status":"succeeded"}'
```

`Idempotency-Key` означает: при повторном запросе с тем же ключом возвращается первоначальный платёж (`200`), новый не создаётся. Как требует формулировка ТЗ, ключ определяет повтор даже если новое валидное тело отличается. Подпись вебхука — необязательный бонус и здесь не реализована; настоящий банк нельзя подключать к этому учебному API без защиты уведомлений.
