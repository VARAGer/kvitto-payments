# Работа с ИИ

Использовал Codex (модель GPT-6) для анализа ТЗ, реализации и проверки кода. Исходный PDF оставался источником требований; результат проверял запуском проекта и тестами, а не принимал ответы модели на веру.

Ключевые запросы с контекстом (формулировки сокращены):

1. «Внимательно изучи PDF тестового задания Junior Python/FastAPI. Выпиши обязательные требования, бонусы и неоднозначности; не начинай писать код до полного понимания ТЗ». Контекст: 3-страничный файл работодателя и требование не переусложнять решение.
2. «Независимо прочитай PDF, составь компактный чек-лист, отметь мелкие условия и неоднозначности. Код не пиши». Это запрос отдельному Requirements Reviewer для сверки прочтения задания.
3. «Реализуй рабочий API платежей, проверь суммы в копейках, идемпотентность, график 3/6/12 месяцев и переходы статусов; затем сравни проект с PDF и проверь тестами». Контекст: матрица требований в `REQUIREMENTS.md` и ограничения тестового задания.

Модель в первоначальном варианте создания БД использовала `Session(session_factory.bind)`. При проверке кода выяснилось, что это ненадёжное обращение к `sessionmaker`: фабрика уже умеет создавать настроенную сессию. Код исправлен на `with session_factory() as session:` до запуска тестов. Отдельно проверено, что `amount` после скидки остаётся целым числом и сумма графика совпадает с ним: простой `amount // months` для каждого платежа потерял бы остаток. Итоговый набор тестов запускается командой `pytest -q`.
