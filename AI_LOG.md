# Работа с ИИ

В процессе выполнения тестового задания использовал Codex (модель GPT-6) как инструмент для ускорения разработки: для анализа требований, подготовки первоначальной реализации, генерации части тестовых сценариев и поиска потенциальных проблем.

Сгенерированные решения не рассматривались как готовый результат без проверки. Проект сверялся с исходным ТЗ, запускался локально, API проверялся автоматическими тестами и отдельными сценариями. В ходе дополнительного аудита первоначального варианта были обнаружены проблемы с конкурентным обновлением статусов вебхуков и проверкой внешнего ключа SQLite. После этого реализация была исправлена, а найденные случаи покрыты регрессионными тестами.

Ключевые запросы с контекстом (формулировки сокращены):

1. «Внимательно изучи PDF тестового задания Junior Python/FastAPI. Выпиши обязательные требования, бонусы и неоднозначности; не начинай писать код до полного понимания ТЗ».
2. «Независимо прочитай PDF, составь компактный чек-лист, отметь мелкие условия и неоднозначности. Код не пиши».
3. «Реализуй рабочий API платежей по требованиям ТЗ, затем проведи повторный аудит: проверь суммы в копейках, идемпотентность, рассрочку, переходы статусов, конкурентные запросы и работу БД».

В первоначальной реализации проверка перехода статуса вебхука выполнялась до записи, поэтому при конкурентных запросах могла возникнуть гонка: два несовместимых обновления одновременно проходили проверку. Дополнительный HTTP-прогон и регрессионный тест воспроизвели проблему. Исправление — условный SQL `UPDATE` по ID и исходному статусу с ответом `409`, если состояние уже изменилось другим запросом.

Также при проверке выяснилось, что SQLite по умолчанию не применял ограничение внешнего ключа. Для каждого соединения была включена проверка `PRAGMA foreign_keys=ON` и добавлен отдельный тест.

После исправлений, рефанда/health и реализации бонусов полный набор тестов проходит: 47 тестов, а также проверки живого API, конкурентных операций, подписи и миграций. Для Codex добавлены правила в AGENTS.md. Подробные результаты находятся в `AUDIT_REPORT.md`.

ИИ использовался как инструмент разработки и проверки. Источником требований оставался исходный PDF тестового задания, а итоговая реализация проверялась по фактическому поведению приложения и тестам.
