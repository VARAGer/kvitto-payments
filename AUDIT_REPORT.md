## Исправления

1. Гонка вебхуков: чтение статуса и безусловная запись позволяли нарушить правила. Теперь условный SQL UPDATE проверяет ID и исходный статус; при 0 изменённых строк — rollback и 409.
2. SQLite не проверял внешний ключ по умолчанию. Connect-event включает `PRAGMA foreign_keys=ON` на каждом соединении.
3. Engine закрывается в `finally` lifespan, включая исключения при завершении.

При повторе временного стенда встретились сохранённый ключ и TIME_WAIT порта. Стенд исправлен: чистая тестовая БД и проверка порта с SO_REUSEADDR. Эти сбои не были ошибками приложения.

Функциональных ошибок в проверенном объёме не осталось. Проверены SQLite и запуск по README. PostgreSQL, несколько одновременно стартующих workers и production-деплой не заявлены. Отправка ссылки работодателю и дата получения задания не подтверждены; полную сдачу нельзя считать завершённой.
