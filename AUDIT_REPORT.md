## Что проверено фактически

**API и деньги.** GET /tariffs, POST /payments, GET /payments/{id}, POST /webhooks/bank выполнены через отдельный Uvicorn. Для 3 тарифов × promo/no promo × card/sbp/трёх сроков installment проверены 30 комбинаций, точные amount/discount/schedule, sum(schedule), остаток в первых платежах и SQL typeof. Промокод проверен в нескольких регистрах. Ответ содержит ровно 10 нужных полей; внутренних полей нет.

**Валидация.** Отсутствующие/null/пустые поля, неправильные типы, enum/email, отрицательные/нулевые/огромные ID, bool/float, неизвестный промокод, сроки, лишние поля, массив/строка вместо объекта, повреждённый JSON, пустое тело, Unicode. Изменений БД при ошибках не было. Обычная coercion Pydantic и игнорирование лишних полей зафиксированы как NOT AN ISSUE: строгого режима в PDF нет.

**Идемпотентность.** Первый запрос, идентичный повтор, другой валидный body, невалидный повтор, рестарт, отсутствие/пустой/длинный ключ, Unicode-заголовок, 50 конкурентных запросов. При невалидном повторе — 422 без второй строки: это стандартная валидация до endpoint; PDF не задаёт исключение для такого случая.

**Статусы и refund.** Все 16 пар статусов проверены с кодом, телом и SQL-результатом. В гонках — допустимое конечное состояние, один 200 и один 409 для несовместимых операций. Возврат сохраняет amount, discount, schedule; проверены pending/failed/refunded/succeeded и 404/422.

**БД.** Сверены колонки, типы, nullable, PK, FK, unique, индексы и обе стороны relationship. Явных дополнительных индексов нет; уникальность обеспечена ограничениями SQLite. FK включён. Прямые попытки вставить несуществующий tariff или повторный ключ дали IntegrityError; после rollback та же Session успешно читала данные. Контекстные менеджеры закрывают сессии, lifespan освобождает engine. Деньги сохраняются целыми числами. Миграции являются способом создания схемы; create_all в запуске нет.

**HMAC.** Алгоритм SHA256, правильный/неправильный секрет, неверная/отсутствующая подпись, изменение символа/пробела/newline, Unicode, lowercase/uppercase hex, malformed/empty body. Используются исходные bytes и compare_digest. При неверной подписи состояние не меняется. Некорректный JSON может отклоняться FastAPI раньше dependency (422), неверный UTF-8 JSON — 400; это NOT AN ISSUE, бизнес-логика не вызывается. Без WEBHOOK_SECRET запуск отклоняется, небезопасного default нет.

**Фильтры.** Без фильтров, email, status, оба через AND; несколько записей, пустой результат, plus-address через URL encoding, сортировка по ID, response schema, 422 на неправильные параметры.

**Health.** Ответ 200 с рабочими таблицами, отсутствие изменения данных, реальные неисправные базы и 503. Ответ не содержит traceback, DATABASE_URL или секрет.
